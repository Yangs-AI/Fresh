**Zotero** is the recommended reference management tool in our research workflow. It supports automatic citation formatting, full-text indexing, and collaborative literature sharing across teams. This tutorial focuses on installing and configuring Zotero, with particular emphasis on plugin setup and group library management. Since Zotero's built-in cloud storage is limited, we also provide instructions for integrating Zotero with external cloud storage services such as OneDrive.

Zotero (/zoʊˈtɛroʊ/) is a free and open-source reference management software used to manage bibliographic data and related research materials such as PDF and ePUB files. Its features include browser integration, online synchronization, in-text citations, footnotes and bibliographies, integrated PDF/ePUB/HTML readers with annotation support, and a built-in note editor. Zotero integrates with Microsoft Word, LibreOffice Writer, OnlyOffice, and Google Docs. Originally developed by the Center for History and New Media at George Mason University, Zotero has been maintained since 2021 by the non-profit Corporation for Digital Scholarship. (Source: Wikipedia - https://en.wikipedia.org/wiki/Zotero)

## Overview

This setup guide will help you:

- Install Zotero and essential plugins.
- Synchronize your library across devices (optionally via OneDrive or other cloud services).
- Collaborate efficiently using Zotero Groups.

## Step 1: Install Zotero and Plugins

### Installing Zotero

Download and install the latest version of **[Zotero](https://www.zotero.org/download/)**, and follow the instructions to install the browser connector. Once installed, you can save references directly to your personal or group library by clicking the browser connector while browsing academic resources online.

Within Zotero, you can organize references into different **collections** according to your needs. A single reference only needs to be added once to the library, but it can appear in multiple collections (internally stored once, with multiple logical references).


### Installing Zotero Plugins

Zotero officially supports a wide range of plugins, listed at:
https://www.zotero.org/support/plugins

In this guide, we recommend several high-frequency and team-enhancing plugins:

1. **[Better BibTeX for Zotero](https://retorque.re/zotero-better-bibtex/)**  
   Enables automatic citation key generation and seamless BibTeX/BibLaTeX export for LaTeX users.

2. **[Zotero PDF Translate](https://github.com/windingwind/zotero-pdf-translate)**  
   Provides instant translation of selected text within PDFs.

3. **[Zotero Reading List](https://github.com/Dominic-DallOsto/zotero-reading-list)**  
   Adds a "Reading List" pane to Zotero, allowing you to quickly mark items for follow-up reading and manage your reading workflow without cluttering your main collections. Especially useful for triaging new papers before formally classifying them.

4. **[Zotero Google Scholar Citation Count](https://github.com/justinribeiro/zotero-google-scholar-citation-count)**  
   Displays Google Scholar citation counts directly in Zotero, helping you assess the impact and popularity of references at a glance. This can be useful for prioritizing reading or evaluating sources.

5. **[Zotero Format Metadata](https://github.com/northword/zotero-format-metadata)**  
   Allows you to batch-format and clean up metadata fields such as title, date, and author. For example, you can standardize title capitalization, fix date formats, and ensure consistency across your library. This is especially valuable for maintaining a clean, professional, and searchable team library.

To install these plugins, open Zotero and navigate to **Tools → Plugins**, then download the corresponding `.xpi` files from the plugin websites and drag them into the `Plugin Manager` window.

Restart Zotero after installation.

## Step 2: Configure Zotero and Plugins

All software and plugin settings can be found under **Edit → Settings**, which opens the `Zotero Settings` window. All tabs and options mentioned below refer to this interface.

Only key recommended settings are described here; other options may be adjusted according to personal preferences.

### Software Settings

1. In the **General** tab, you may change the default tools used to open PDFs/EPUBs/Snapshots. Zotero is used by default.
2. It is recommended to enable cloud synchronization. In the **Sync** tab, register or log in with your Zotero account. By default, Zotero syncs both metadata and attachment files. Our team convention is to use **OneDrive (or another personal cloud drive) for attachments in My Library**, while keeping **Zotero storage enabled for Group Libraries** so that shared papers remain available to the whole team (see Step 2).

### Plugin Settings

#### Better BibTeX for Zotero

1. In the **Export** tab, set **Item Format** to **Better BibTeX** or **Better BibLaTeX**.

   **Background knowledge:** What are *BibTeX* and *BibLaTeX*?  
   What is the relationship between `bibtex` vs. `biber`, and `biblatex` vs. `natbib`?

   These terms refer to different but closely related components in the LaTeX bibliography ecosystem, including bibliography formats, citation packages, and backend processors.  
   They are often confused because they are frequently used together but serve distinct roles.

   The figure below provides a concise overview of how these components relate to one another.  
   ![Relationship between Bibliographic Terminology in TeX](./figures/bib.png)
   For a detailed explanation, see this StackExchange discussion:  
   https://tex.stackexchange.com/questions/25701/bibtex-vs-biber-and-biblatex-vs-natbib


   **How to choose:**

   - If you are writing papers using traditional BibTeX-based templates (e.g., IEEE, ACM, NeurIPS, ICML, ICLR) with `.bst` style files, choose **Better BibTeX**. This is the most compatible and widely used option in computer science and engineering, and works reliably with Overleaf and journal submission systems.
   - If you are using modern templates that explicitly rely on `biblatex` (e.g., Springer LNCS, Elsevier, Nature, or thesis templates), choose **Better BibLaTeX**, which supports richer metadata such as `url`, `urldate`, and `eprint`.

   **In short:**
   - *Better BibTeX* → Stable, general-purpose, recommended for most CS conferences and journals.
   - *Better BibLaTeX* → More expressive, suitable for modern or interdisciplinary templates.

   **Recommendation:** For team collaboration and shared libraries, standardize on **Better BibTeX** to avoid compatibility issues.

2. Under **Citation Keys**, set the citation key formula to:
   ```
   auth.lower + year + shorttitle(3, 3).lower
   ```
   This is the format currently adopted by our group. Advanced customization options can be found in the official documentation:
   https://retorque.re/zotero-better-bibtex/citing/index.html

3. Under **Export**:

   - **BibTeX section**:
     - Enable *Export unicode as plain-text LaTeX commands*.
     - Set *Add URLs to BibTeX export* to:
       ```
       in the 'url' field
       ```

   - **BibLaTeX section**:
     - Enable *Use BibLaTeX extended name format* (only if compiling with `biblatex/biber`).
     - Enable *add use-prefix when family name has a prefix*.

   - **Fields**:
     - In *Fields to omit from export*, enter:
       ```
       file,eprint,eprinttype,eprintclass,abstract
       ```
     - Set *Export language as* to `langid`.
     - Set *When item has DOI and URL* to `both`.

   - **Miscellaneous**:
     - Do **not** enable *Automatically abbreviate journal title if none is set explicitly*.
     - Enable *Apply title-casing to titles* only if required by the target venue.

#### Zotero PDF Translate

Open the **Translate** tab and configure as follows:

1. **General**:
   - Enable *Automatically Translate Selection*.
   - Do **not** enable *Automatically Translate Annotation*, as it replaces original annotations with translations.
2. **Service**:
   - Set *Translation Service* to **Google (API)**.
   - Configure *Translate From* according to your needs.
   - Set *Dictionary Service* to **Collins Dict (en→zh)** or **FreeDictionaryAPI (en→en)**.
3. Keep other options at their default values unless specific customization is required.

#### Zotero Google Scholar Citation Count

After installing **[Google Scholar Citation Count](https://github.com/justinribeiro/zotero-google-scholar-citation-count)**, add the **Citation Count** column in the Zotero item list (right-click the column header area to enable it).

When a new paper is saved, the plugin automatically attempts to fetch citation counts from Google Scholar. This makes it easier to estimate paper visibility and helps prioritize reading.

If citation counts cannot be fetched due to network restrictions, configure a custom Google Scholar endpoint in the plugin settings.

#### Zotero Reading List

After installing **[Zotero Reading List](https://github.com/Dominic-DallOsto/zotero-reading-list)**, we recommend this workflow-oriented setup:

1. Enable *Automatically label new items when you add them to Zotero* and set the default label to **New**.
2. Enable *Automatically change the read status of items when opening an attached file*.
3. In *Custom Status Changes When Opening Item*, add these mappings:
   - **New** → **In Progress**
   - **To Read** → **In Progress**

Recommended workflow:

- Newly added papers start as **New** by default.
- If you decide a paper should be read later, manually change status to **To Read**.
- When you open the attachment for actual reading, status moves to **In Progress** automatically.

To make these markers visible in the main list, right-click the Zotero item list header and enable the **Read Status** column.

#### Zotero Format Metadata (Displayed as Linter)

After installing **[Zotero Format Metadata](https://github.com/northword/zotero-format-metadata)**, it may appear as **Linter** in the plugin page.

There is currently no mandatory configuration for our team. The main value is batch-formatting metadata for selected references, such as normalizing date strings into ISO-style formats and cleaning inconsistent fields.

Advanced option (optional): request a Semantic Scholar API key and connect it in plugin settings to potentially retrieve richer or more accurate metadata.

Request form:
https://www.semanticscholar.org/product/api#api-key-form

#### Optional: Configure Cloud Storage

Zotero's built-in cloud storage is limited, and attachment files (PDFs, snapshots) consume most of the space, while metadata itself is lightweight. To balance personal flexibility with team-wide sharing, our recommended setup is:

- Use **OneDrive** (or another personal cloud drive) to synchronize attachment files in **My Library**.
- Use **Zotero storage** for **Group Libraries**, so that shared papers and their attachments remain available to all group members.

This separation works well in practice: your personal library stays under your own cloud account, while the lab can maintain a stable shared literature pool inside the Zotero Group.

Example using OneDrive (other services follow similar logic):

1. Open **Settings → Sync**, and configure file sync as follows:
   - Keep *Sync attachment files in My Library using Zotero storage* **disabled**.
   - Keep *Sync attachment files in group libraries using Zotero storage* **enabled**.
   - In **Choose Libraries...**, include the Group Libraries you actually need. If you belong to multiple groups, you may leave unrelated ones unchecked.
2. Move Zotero's local `storage` directory to a folder within OneDrive (e.g., `C:\Users\Fresher\OneDrive\Zotero`).  
   If another device is already synced, skip this step, close Zotero, delete the local `storage` folder, and proceed to the next step.
3. Create a directory junction (Windows example; use equivalent symlink commands on macOS/Linux):

   ```powershell
   mklink /J "C:\Programs\Zotero\storage" "C:\Users\Fresher\OneDrive\Zotero\storage"
   ```
   or
   ```bash
   ln -s /path/to/your/OneDrive/Zotero/storage /path/to/your/Programs/Zotero/storage
   ```

After this, files in your personal library will be synchronized through OneDrive, while files in Group Libraries will continue to be synchronized through Zotero storage.

Under this setup, shared papers in the Group Library can still be selectively copied into your personal library by drag-and-drop. This allows students and researchers to keep a curated personal collection while also contributing valuable references back to the Group Library when appropriate.

## Step 3: Join the Group Library

For collaborative citation sharing (It is recommended to configure Cloud Storage before this step.):

1. Provide your Zotero account username or registered email to your advisor or group administrator.
2. Once invited, you will see the shared **Group Libraries** in the left panel.
3. You may drag useful papers from the Group Library into your personal library if you want to keep your own curated subset.
4. Add papers you have read or found useful to the Group Library, ensuring accurate metadata and appropriate tags, so the whole team can benefit from them.

The shared library accelerates citation reuse and preserves the collective research memory of the team.

## Step 4: Quickly Add References

Install the **Zotero Connector** browser extension from:
https://www.zotero.org/download/

When browsing academic websites, the connector captures metadata, PDFs, and snapshots and saves them to Zotero.

To ensure references are saved into the correct collection:

1. Select the target collection in the connector popup when saving; or
2. Select the desired collection in Zotero first, keep it active, then click the connector in your browser.

Note: Please ensure you access the correct paper via the correct DOI link.

### Best Practices for Adding References to the Team Library

To ensure the team library remains clean, reliable, and easy to maintain, please follow these guidelines when adding new references:

1. **Always Use Official Sources**
   - Add papers from their official publisher pages whenever possible (e.g., publisher website, arXiv, or conference/journal homepage).
   - Ensure each entry includes a valid DOI (Digital Object Identifier) if available. Avoid adding items without DOIs unless absolutely necessary.
   - For web resources, only add those that are essential and not available in formal publication venues. Avoid adding blog posts, random web pages, or non-peer-reviewed content unless specifically required for a project.

2. **Metadata Quality**
   - Double-check that metadata (title, authors, date, journal/conference, DOI, etc.) is accurate and complete. Use the **Zotero Format Metadata** plugin to standardize and clean up fields as needed.
   - Avoid duplicate entries. Search the library before adding a new item.

3. **Classification and Organization**
   - Assign each reference to the most relevant collection(s). Use collections to group by topic, project, or purpose, but avoid excessive or overly granular classification.
   - Maintain a balance: be diligent in classifying, but do not create too many small or redundant collections. Over-classification can make the library harder to navigate.
   - Use tags for additional context or temporary grouping (e.g., "to-read", "important", "reviewed").

4. **Group Library Etiquette**
   - When adding to the Group Library, ensure the reference is useful for the whole team and not just for personal use.
   - Add meaningful notes or tags if the reference is particularly important, controversial, or requires follow-up.

5. **Regular Maintenance**
   - Periodically review and clean up the library: remove duplicates, fix metadata, and reorganize collections as the team's focus evolves.

By following these practices, we can keep the team library sustainable, searchable, and valuable for everyone.

## Summary

Zotero, combined with Better BibTeX, PDF Translate, Reading List, Google Scholar Citation Count, and Format Metadata, forms a **lab-standard literature environment** that is reproducible, searchable, and collaboration-friendly.

With OneDrive for personal libraries and Zotero storage for shared Group Libraries, every team member can maintain a flexible personal workflow while contributing to a continuously evolving citation ecosystem for the lab.
